## Findings

**1. (m) The d′ formula, the "d ≤ 500" sentence and the worked table disagree for arms with min n_fit − 1 < d ≤ 500; the Birds row is such a case.** §6.4 keeps "Arms with d ≤ 500 are unchanged (no-op), and this is reported", and `width_plan` returns `native` whenever `d_feat ≤ 500` before computing d′. But the §6.4 formula d′ = min(500, d, min n_fit − 1) and §1.5's single no-op definition "d′ = d" (review-10 finding 6) make Birds multiview (d = 6·38 + 1 = 229, min n_fit − 1 = 184) a `pca184` arm, and the worked table prints exactly that (Birds | 186 | 185 | **184**). The same holds for every §1.2 set's multiview arm (Letter sets: width 97, n_fit − 1 ≈ 91). The branch is unreachable in practice (none of these datasets can project above 72 device-hours), but the deposited text contradicts itself and its table contains a value the code cannot emit. Fix: state once that the d′ rule applies only to arms with d > 500 (arms with d ≤ 500 stay `native` whatever min n_fit is, which is what the code does and what TabPFN's limit motivates), and either drop the Birds row or annotate it "width 229 ≤ 500: `native` regardless". §1.5's "no-op, defined as d′ = d" then needs "for arms with d > 500" too.

**2. (m) §1.3's tie tolerance covers "(or SDs)"; the DECISIONS row and the code cover means only.** "T03 decisions, part 2" says "An inner-mean tie is |Δ| ≤ 1e-12 absolute". `select()` applies `MEAN_TIE_ABS` to means and `tie_key` compares SDs exactly. The plan says "two inner means (or SDs) are tied when |Δ| ≤ 1e-12". Two candidates with SDs 1e-13 apart would be decided by SD in the code and by method name in the plan. Either delete "(or SDs)" (matching the decided rule) or add an SD tolerance to the code and a line to DECISIONS. Delete is the faithful choice.

**3. (m) The two construction acceptance checks are stated as stops but are not in the code that constructs.** H2-A step 4: "`construction.json["duplicates"]` must list exactly the dropped rows … and the pool sizes must equal those above; a mismatch stops the construction." H2-B: "the fold means written to each `purged/masks.json` must reproduce the table below at the table's printed precision; a mismatch stops the H2-B runs." `h2a_rebuild.py` writes the report and checks structural invariants (⌊n/10⌋ pools, no remainder or dropped row in a bag, no overlap) but holds no expected list; `h2b_masks.py` writes `masks.json` and holds no expected table; `tests/test_h2.py` exercises the mechanism on synthetic data only. As written, the stop depends on someone comparing by eye after the files exist. Either put the expected constants (the 13 rows, the ten Medical and ten Corel5K pool sizes, the H2-B table rounded as printed) into the two scripts, or name a check script that runs at C-queue step 2 before anything reads the constructions, and say so in the plan.

(b) The History row says "The addendum (`3c720d8`) was reviewed in rounds 10–11"; round 11 reviews `589a980`.
